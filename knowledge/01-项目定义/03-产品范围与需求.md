## 需求优先级

- `P0`：首个可用闭环必须具备。
- `P1`：闭环稳定后优先补齐。
- `P2`：后续增强，不阻塞首版。

## 三个产品端

ArcMind V2 包含三块独立代码和三个独立部署单元：

| 产品端 | 交付形态 | 是否必需 | 生命周期 |
|---|---|---:|---|
| 手机 Web 端 | 浏览器 Web 应用，可后续增强为 PWA | 是 | 随页面打开和关闭，不承担长期后台任务 |
| 云端后端 | 部署在 VPS 的长期运行服务和数据组件 | 是 | 持续在线，维护业务事实、编排和异步任务 |
| 工作机客户端 | 用户工作电脑上的安装程序和常驻执行进程 | 否 | 用户按需安装，主动连接云端并执行授权任务 |

三端可以采用不同技术栈和独立版本，但必须通过共享、版本化的 API 与事件契约协作。工作机的安装器只是工作机客户端的交付组件，不应被当成第四个产品端。

## 手机 Web 端需求

| 编号 | 优先级 | 需求 | 验收摘要 |
|---|---|---|---|
| MW-001 | P0 | 用户可以使用后台预置的单一账号密码登录和退出 | 不提供公共注册；会话可恢复，失效状态有明确提示 |
| MW-002 | P0 | 用户可以发起和结束实时语音会话 | 页面前台可持续收发音频，状态可见 |
| MW-003 | P0 | 实时会话支持用户打断 AI 播放 | 打断后旧音频停止，系统转入收听或处理状态 |
| MW-004 | P0 | 显示连接、收听、思考、说话和异常状态 | 用户无需猜测当前是否仍在工作 |
| MW-005 | P0 | 对话中形成任务时展示任务摘要并请求确认 | 未确认任务不得进入可执行状态 |
| MW-006 | P0 | 查看任务列表、详情、进度和结果 | 云端与工作机进度采用统一状态语义 |
| MW-007 | P1 | 支持文字输入作为语音失败时的降级入口 | 不支持麦克风时仍能完成核心交互 |
| MW-008 | P1 | 接收任务完成、失败、阻塞和提醒消息 | 用户能从消息进入对应任务或提醒详情 |
| MW-009 | P2 | 提供可安装的 PWA（渐进式 Web 应用）体验 | 不经过应用商店即可添加到桌面 |

## 云端后端需求

| 编号 | 优先级 | 需求 | 验收摘要 |
|---|---|---|---|
| CB-001 | P0 | 管理用户身份和 Web 会话 | 跨设备访问受控，异常会话可撤销 |
| CB-002 | P0 | 管理实时会话并隔离语音供应商差异 | 上层业务不依赖供应商私有事件名称 |
| CB-003 | P0 | 维护对话上下文和可审查的长期记忆 | 记忆可追溯、可更正、可删除 |
| CB-004 | P0 | 主 Agent 负责意图澄清、方案形成和任务拆解 | 任务执行不由实时语音模型单方面决定 |
| CB-005 | P0 | 维护统一任务表、任务步骤和状态事件 | 所有状态变化可追溯且支持幂等处理 |
| CB-006 | P0 | 将合适任务路由到云端能力或在线工作机 | 路由依据、目标设备和结果均可查询 |
| CB-007 | P1 | 管理定时提醒和通知 | 触发、投递和读取状态可追踪 |
| CB-008 | P1 | 提供模型、供应商和能力策略配置 | 切换供应商不破坏历史任务与记忆 |
| CB-009 | P1 | 提供审计、指标和故障诊断 | 能区分浏览器、云端、供应商与工作机故障 |

## 工作机端需求

| 编号 | 优先级 | 需求 | 验收摘要 |
|---|---|---|---|
| WS-001 | P1 | 作为可选扩展绑定到同一用户身份 | 没有工作机不影响手机与云端基础能力 |
| WS-002 | P1 | 主动向云端建立长连接，不要求公网 IP | 普通家庭和办公网络可连接 |
| WS-003 | P1 | 上报在线状态、能力清单和当前任务状态 | 云端只派发设备声明支持的能力 |
| WS-004 | P1 | 通过受控适配器调用 Codex CLI 等本地执行工具 | ArcMind 不重写这些工具的核心能力 |
| WS-005 | P1 | 对敏感或不可逆动作执行本地或远程确认 | 未确认时保持等待，不静默越权 |
| WS-006 | P1 | 流式回传日志摘要、进度、产物引用和最终结果 | 手机端可持续查询，不依赖保持通话 |
| WS-007 | P2 | 支持断线恢复、任务续跑和多个工作机选择 | 重连不会重复执行已确认步骤 |

## 实时语音质量要求

- 必须支持低延迟双向音频或等价的流式链路。
- 必须支持用户在 AI 说话时打断，并清理未播放音频。
- 音色应自然、清晰，避免明显机械感；最终供应商需要通过真人主观试听。
- 语音层需要提供转写或结构化文本给主 Agent，不能只输出不可检索音频。
- 网络抖动、供应商限流和模型不可用时应有清晰降级与重试策略。

## 通用质量要求

- 安全：默认最小权限，高风险动作必须确认，跨端通信必须加密。
- 隐私：会话、记忆和任务提供删除、保留期和导出边界。
- 可观察：关键状态变化产生可关联事件，不记录不必要的私密正文。
- 可恢复：断线和进程重启后能恢复任务真实状态。
- 可替换：语音供应商、推理模型和执行器通过稳定接口隔离。
- 可验证：每个阶段在开发前补齐接口、状态机和验收用例。
