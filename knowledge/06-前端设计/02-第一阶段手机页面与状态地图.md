## 页面地图

```text
启动
 ├─ 有效会话 -> /conversations/new
 └─ 无会话   -> /login -> /conversations/new

/conversations/new -> /conversations/{conversation_id}
任一受保护页面 -- 会话失效 --> /login?reason=session_expired
```

| 页面 | 用户目标 | 关键动作 | 成功出口 |
|---|---|---|---|
| 账号密码登录 | 建立本人 Web 会话 | 输入账号和密码、提交 | 新文字会话页 |
| 会话失效 | 恢复访问而不丢失理解 | 查看统一提示、重新登录 | 登录完成后回到安全可恢复页面 |
| 新文字会话 | 开始对话 | 创建会话 | 文字会话页 |
| 文字会话 | 发送、观察、取消和重试回答 | 发送文字、取消生成、失败后重试 | 最终轮次进入会话历史 |

## 身份状态

### 账号密码登录

| 状态 | 界面行为 | 可执行动作 |
|---|---|---|
| `idle` | 账号和密码输入可编辑，提交可用 | 提交 |
| `submitting` | 保留账号，密码只留在当前输入控件中，防止重复提交 | 无 |
| `invalid` | 统一提示账号或密码错误，不指出具体字段 | 修改后重试 |
| `rate_limited` | 显示可再次尝试的剩余时间 | 倒计时结束后提交 |
| `authenticated` | 建立会话，清空密码输入 | 进入文字会话 |
| `network_error` | 说明连接失败，不推断账号状态 | 重试 |

客户端不得持久化密码，也不得用响应差异推断用户登记情况。服务器负责最终验证和最小限速。

### 会话失效

- 普通请求返回 `AUTH_SESSION_EXPIRED`，或事件流因同一原因关闭时，统一进入会话失效流程。
- 立即停止发送、重连和取消请求，清除仅内存中的临时回答；已持久化轮次不在客户端删除。
- 只保存不含敏感内容的返回目标。重新登录后重新查询会话事实，不恢复旧的事件流游标。
- 用户主动退出与服务器过期使用不同提示，但都不得继续显示“仍在线”。

## 文字会话状态

```text
ready -> submitting -> queued -> streaming -> completed
                    \-> failed -> retrying
queued/streaming -> cancelling -> cancelled
queued/streaming -> reconnecting -> streaming/completed/failed/cancelled
任一受保护状态 -> session_expired
```

| 状态 | 用户看到的事实 | 允许动作 |
|---|---|---|
| `ready` | 已持久化最终轮次和可编辑输入 | 发送 |
| `submitting` | 本次文字正在提交，不重复追加用户轮次 | 等待 |
| `queued` | 用户轮次已保存，回答等待生成 | 取消 |
| `streaming` | 临时回答随快照和增量更新，并明确不是最终轮次 | 取消 |
| `reconnecting` | 保留最后展示快照，显示正在恢复 | 取消本地等待；连接恢复后再发服务端命令 |
| `completed` | 最终助手轮次由普通查询也可恢复 | 继续发送 |
| `failed` | 显示稳定错误摘要和是否可重试 | 重试或继续新消息 |
| `cancelling` | 已提交幂等取消，不再接受旧增量 | 等待终态 |
| `cancelled` | 明确本次未形成最终助手轮次 | 重试或继续新消息 |

## 事件处理顺序

1. 发送文字时生成新的幂等键；同一次界面重试复用该键，用户明确重新提问才生成新键。
2. 收到 `response.snapshot` 时用完整文本替换临时回答，并记录快照版本和事件序号。
3. 只追加序号连续且高于已处理序号的 `response.delta`；重复事件直接忽略。
4. 发现序号缺口时停止拼接并重连，等待新的权威快照。
5. 收到完成、失败或取消终态后关闭事件流并查询会话详情；查询结果是最终显示依据。
6. 用户取消后进入 `cancelling`，迟到的增量不得再次显示；重复取消必须得到同一终态。
7. 重连超出服务端重放窗口时丢弃临时文本并查询响应或会话事实；不得把残缺回答标为完成。

## 错误展示规则

| 错误码 | 页面行为 |
|---|---|
| `AUTH_INVALID_CREDENTIALS` | 登录页统一提示账号或密码错误 |
| `AUTH_SESSION_EXPIRED` | 进入会话失效流程 |
| `RATE_LIMITED` | 使用 `Retry-After` 倒计时，不自动密集重试 |
| `RESOURCE_NOT_FOUND` | 返回安全入口，不暴露其他用户资源是否存在 |
| `RESPONSE_IN_PROGRESS` | 刷新当前会话事实，不创建重复回答 |
| `MODEL_RATE_LIMITED`、`MODEL_TIMEOUT`、`MODEL_UNAVAILABLE` | 保留用户轮次，按 `retryable` 提供显式重试 |
| `RESPONSE_REPLAY_WINDOW_EXPIRED` | 丢弃临时拼接，重新查询会话最终事实或等待新快照 |

所有错误都显示用户可理解的中文摘要；`correlation_id` 仅作为问题追踪编号，不展示内部堆栈、供应商名称或凭据。

## 交互约束

- 输入、发送、取消和重试必须有稳定尺寸与明确禁用状态，异步文字变化不得导致布局跳动。
- 账号和密码输入有可访问标签，错误不只靠颜色表达；焦点在错误后返回对应输入或提示。
- 流式回答使用非打断式状态提示，不能让每个增量触发屏幕阅读器重复朗读整段内容。
- 页面刷新、前后台切换和短暂断网后都必须先查询服务端事实，再恢复可执行动作。
- 页面视觉继承 `main` 主分支第一版 ArcMind 弦核界面：空闲时保持中心弦核与悬浮输入区，发送后以工作台式面板展示用户轮次和临时回答。
- `streaming` 只将弦核切换为第一版的思考模式，并按真实增量触发受控脉冲；不得用固定定时器或随机值伪造音频和 token（文本片段）活动。
- 多个增量、快照和最终查询只能更新现有页面内容，不得替换粒子画布或创建第二个动画循环。
