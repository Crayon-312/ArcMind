# 决策 0004：单仓库管理三套独立应用

状态：accepted
日期：2026-07-30

## 背景

ArcMind V2 需要手机 Web、云端后端和工作机客户端三块代码。需要确定它们是三个 Git 仓库，还是同一仓库中的三个独立应用。

## 决策

- 保持当前 ArcMind V2 单一 Git 仓库。
- 在 `apps/` 下建立 `mobile-web`、`cloud-server` 和 `workstation-client` 三套应用。
- 在 `packages/contracts` 保存语言无关的 API 和事件契约源。
- 三套应用独立构建、测试、发布和回滚，禁止相互引用内部代码。
- 云端部署配置放在 `infrastructure/`，不创建第四个业务应用。

## 理由

- 当前由单人开发，跨端契约仍会频繁调整。
- 端到端变更可以在一次审查和提交中保持一致。
- Codex 等开发工具可以在一个项目上下文内检查全链路影响。
- 单仓库不妨碍独立部署，目录边界和契约门禁足以保持应用隔离。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 应用边界逐渐混乱 | 模块卡片、路径规则和依赖检查 |
| 所有应用被迫使用同一技术栈 | 只共享语言无关契约，允许独立依赖 |
| CI 越来越慢 | 按路径选择任务，并保留契约集成检查 |
| 发布互相阻塞 | 应用与契约独立版本，定义兼容窗口 |

## 替代方案

三个独立仓库目前不采用，原因是会提前引入跨仓库版本、契约发布和多任务协调成本。未来出现团队或权限隔离需求时可以重新评估。

## 实施约束

- `pnpm workspace` 只管理 TypeScript 应用和包；Python 云端使用独立的 `uv` 项目与锁文件。
- 根目录只提供跨语言统一入口，不允许用共享运行时代码破坏三套应用边界。
- 代码骨架仍需等第一阶段设计门禁通过后创建。
