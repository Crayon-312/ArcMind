## 当前阶段与下一步

当前已经退出[MVP 阶段 1：身份与文字基线](../01-项目定义/07-MVP能力与阶段边界.md)。生产账号密码、公网文字、旧用户数据合并、备份和重启恢复全部通过；唯一下一业务阶段是任务闭环，必须先建立并确认新任务舱。

阶段 1 完成后的唯一下一业务阶段是“任务闭环”：先定稿任务领域对象、页面状态、机器契约和专项测试，再实现任务草稿、明确确认、状态与一个低风险云端执行器。任务阶段通过后才进入实时语音；长期记忆、提醒和工作机不得提前并行铺开。

## 讨论阶段能否修改正式文档

不能。开发协作 Agent（智能协作助手）在纯讨论阶段只能修改状态为 `draft` 的[任务舱](../14-开发方案/00-开发方案地图.md)，不能修改正式知识、代码或配置。用户确认完整方案和有序任务清单后，任务舱才能进入执行；代码与正式知识在同一任务中验证并一起发布。

这里的开发协作 Agent 与 ArcMind 产品中的[主 Agent 运行时（草案）](../20-Agent运行时/02-主Agent运行时模块.md)不是同一个系统。产品主 Agent 的业务权限规则不能替代开发协作门禁。

依据：[知识库维护规范](./知识库维护规范.md)、[Obsidian 任务隔离决策](../10-架构决策/0010-obsidian-task-publication.md)。

## 当前应该怎样登录

当前代码、OpenAPI（开放式接口描述规范）、手机 Web 和生产只提供单一账号密码登录，不提供公共注册、邀请、找回密码、验证码或 SMTP（简单邮件传输协议）投递。真实 PostgreSQL（关系型数据库）集成与生产验收已经覆盖旧用户原位绑定、密码登录、安全会话、两档数据库权限、备份及重启恢复。

账号由受控部署配置提供：`ARCMIND_LOGIN_USERNAME` 默认使用 `owner`，`ARCMIND_LOGIN_PASSWORD_HASH` 保存部署时生成的密码摘要。原始生产密码只在部署交付时单独提供给用户，不写入仓库、知识库、镜像或日志；修改配置中的密码摘要即可完成受控轮换。

依据：[单一账号密码身份基线](../10-架构决策/0018-simple-login-identity.md)、[账号密码迁移任务舱](../14-开发方案/0016-simple-login-and-database-hardening.md)。邮箱验证码旧方案只保留为已废弃决策和归档历史，不进入当前运行手册。

### 邮箱验证码为什么收不到

2026-08-14 以前的内部测试版本把验证码只投递到服务器本地 Mailpit（测试邮件捕获服务），所以外部邮箱当时收不到验证码。当前仓库和生产已经删除验证码、SMTP（简单邮件传输协议）、Mailpit、公共注册及其监听；现在应使用受控交付的 `owner` 账号密码登录，不再排查或恢复邮件验证码。

## 旧任务舱 0009 是否还能执行

不能。[第一阶段开发入口门禁历史任务](../14-开发方案/0009-phase-1-entry-gate.md)已经标记为 `superseded`（已替代），其中邮箱验证码、SMTP 和旧机器契约清单只作为历史证据保留，禁止继续执行。当前身份实施只依据[任务舱 0016](../14-开发方案/0016-simple-login-and-database-hardening.md)；证书续期、真机、离机备份和真实模型等未关闭事项依据[已知问题地图](../13-已知问题/00-已知问题地图.md)，不能从 0009 的旧清单恢复。

## 当前生产模型是什么

当前生产仍使用确定性测试模型。DeepSeek V4 Pro（深度求索主模型候选）已经被选为首个真实主 Agent 模型，但尚无配置生产密钥或接入生成请求路径的发布证据，因此“已经选型”不能表述为“已经在生产启用”。

依据：[首个模型供应商决策](../10-架构决策/0015-first-model-provider.md)、[安全与部署边界](../08-安全与合规/01-安全与部署边界.md)。

## 新增或修改 API 需要同步什么

非平凡 API（应用程序接口）变更先建立或更新任务舱，然后按以下顺序执行：

1. 在[接口与事件地图](../04-接口与事件/00-接口与事件地图.md)确认业务语义、公开边界、兼容性和错误码。
2. 修改 `knowledge/04-接口与事件/openapi/phase-1.yaml` 或对应机器 Schema；它们是审定契约输入。
3. 运行 `pnpm contracts:generate`，更新 `packages/contracts/src/generated/` 生成类型，不手工复制字段。
4. 同步云端实现、手机 Web 消费方及受影响的前后端设计；跨模块调用不得绕过公开契约。
5. 更新契约、后端、前端和端到端测试，并按[测试与验收地图](../11-测试与验收/00-测试与验收地图.md)验证兼容与失败路径。
6. 验证通过后同步领域地图、当前知识、任务舱和[发布记录](../15-发布记录/00-发布记录地图.md)。

讨论中的接口候选只能留在任务舱或明确标记为草稿的契约文档中，不能提前覆盖机器契约或当前运行事实。
