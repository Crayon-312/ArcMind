# 方案落实台账：知识事实与检索质量加固

## 目标与边界

### 业务目标

让人类与 Agent（智能协作助手）从统一知识库获得相同、可追溯且不会混淆草稿与当前事实的答案；标准 Markdown（轻量标记文档）关系既服务 Obsidian（本地知识库工具）关系图，也进入 Agent Context OS（智能协作上下文操作系统）检索。

### 本次包含

- 修正迁移后仍标记为当前事实的旧路径、旧数量和旧实施状态。
- 建立开发协作、生产邮件、生产模型和 API（应用程序接口）变更的高频事实入口。
- 让 Obsidian 来源提取标准 Markdown 内部链接，并用于关系感知检索。
- 默认检索优先当前事实，同时保留显式状态过滤能力。
- 增加当前知识依赖草稿时必须明确标注的项目门禁。
- 清理已解决问题、日期漂移和任务地图中的陈旧描述。

### 本次不包含

- 不修改 ArcMind 产品业务代码、接口行为、数据库或生产服务器。
- 不把未确认的实时语音、工作机、长期记忆和外部凭据结论提升为当前事实。
- 不引入向量数据库、搜索服务或新的后台进程。
- 不推送远端仓库；推送仍需用户单独授权。

## 证据与判断

### 已确认事实

- 当前 101 条索引知识、820 条去重关系、0 断链和 0 关系孤岛均通过现有门禁。
- 索引中的 `links` 总数为 0；上游 0.2.0 只提取 `[[Wiki 链接]]`，而 ArcMind 使用标准 Markdown 链接。
- 默认检索不给 `current` 状态优先级，17 条草稿与 84 条当前知识平权参与排序。
- 真实查询已复现开发协作与产品 Agent 混淆、测试邮件与真实邮箱混淆、模型选型与生产启用混淆。
- 两篇当前文档仍陈述旧 `docs/` 来源、122 条旧数量或“工程尚未实现”的历史状态。
- Agent Context OS 上游 `main` 仍为固定提交 `fd84369ae9fd1d88df222d18a8519fba87592f4e`，没有可直接升级的新提交。

### 合理推断

- 关系数据进入索引并进行低权重邻接加分，可以改善跨文档召回，但不能替代直接词义命中和事实复核。
- 当前事实状态加权比默认排除草稿更合适，因为“待定、风险、开放问题”查询仍需要找到草稿。

### 假设与开放问题

- Obsidian 默认关系图查询的视觉效果仍需用户在桌面软件实际打开确认；自动检查只能验证 JSON（结构化数据格式）和路径配置。
- 通用补丁在上游正式发布前由 ArcMind 的包管理补丁固定；是否回提上游不在本任务授权范围内。
