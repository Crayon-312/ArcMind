# 账号密码登录与数据库并发收敛

## 业务目标

把当前本人优先的登录链路从邮箱验证码收敛为单一账号密码登录，同时用最小复杂度修复数据库账号权限和文字响应并发问题。

## 已确认范围

- 本阶段先更新目标设计和知识库，再单独实施代码、数据库迁移、机器契约和部署。
- 删除当前目标中的邮箱验证码、SMTP（简单邮件传输协议）、Mailpit（测试邮件捕获服务）登录依赖和找回流程。
- 数据库账号只拆为所有者/迁移账号与运行账号两档。
- 必须修复相同幂等键并发与同一会话并发生成问题。
- 不扩展公开注册、多用户、角色权限、密码找回或复杂账号管理。
- 2026-08-14 用户进一步确认公共注册不是冻结功能，而是从当前知识、机器契约和运行代码中完全移除；只保留旧生产数据库升级与必要回退所需的历史迁移结构。

## 过渡门禁

- 代码与隔离数据库验证已经完成，生产仍运行邮箱验证码旧实现；不得把账号密码描述为已经上线。
- 机器契约与生成类型必须和代码在 AUTH-02 同一提交中更新，避免当前客户端立即失配。
- 数据库迁移前必须备份；不得直接删除用户、会话、对话、响应或队列事实。
- 本任务不授权修改或部署生产环境；生产操作必须另行明确执行并记录验收证据。

## 实施证据

- 2026-08-13：OpenAPI、生成类型、FastAPI（Python 接口框架）、手机 Web、数据库迁移和配置已切换为单一账号密码；SMTP 与 Mailpit 运行依赖已移除。
- 2026-08-13：WSL 隔离 PostgreSQL 18.4 完成 35 个后端测试，并用受限运行账号复跑登录、并发和耐久队列测试；`pg_dump -Fc` 备份结构检查通过。
- 2026-08-14：当前产品、实施顺序、前端、后端和公开 API 中的公共注册目标已完全删除；账号密码机器契约与仓库实现状态已校正，移除未使用的邮箱校验依赖，并增加注册/验证码公开身份路由防回归测试。
- `users.email` 仅作为旧生产用户首次绑定期间的数据迁移字段保留，不参与注册、登录或公开响应；必须等 AUTH-04 证明旧用户已安全绑定后，才能通过后续迁移删除，禁止为了文本清零提前破坏旧会话和对话归属。
- 迁移降级会重建空验证码表，并为没有旧邮箱的新用户生成仅供结构回滚的无效占位邮箱；旧验证码挑战数据不可恢复。生产降级只能在备份与明确回退方案下执行。
- AUTH-04 和 AUTH-05 保持待办：尚未获授权部署生产，也未完成公网登录、Cookie、备份、重启与用户行为验收。
