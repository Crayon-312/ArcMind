# 方案落实台账：继承第一版 ArcMind 视觉与动画

## 目标与边界

### 业务目标

让 V2 手机 Web 在保留当前账号密码、云端会话和流式回复能力的前提下，继承 `main` 主分支第一版 Electron 前端中已经长期打磨的 ArcMind 视觉语言与 3D 粒子动画，消除当前临时聊天皮肤和回复期间随机闪动。

### 本次包含

- 以 `origin/main` 当前第一版 Electron 前端为视觉事实源，迁移中心粒子核心、环境背景、状态读数、消息展示和输入区的视觉结构。
- 复用第一版粒子核心、性能分级、状态信号和真实回复脉冲逻辑；文字回复不得生成随机音频或随机脉冲。
- 保留 V2 账号密码登录、会话恢复、SSE 流式回复、取消、退出和移动端安全区域行为。
- 为手机窄屏建立等价布局，不迁移 Electron 专属窗口、文件系统或桌面桥接行为。
- 补充动画信号和流式回复回归测试，并进行实际渲染检查。

### 本次不包含

- 不恢复 `main` 的旧业务代码、SQLite 本地存储、桌面设置、记忆管理或工作台实现。
- 不接入实时语音、真实模型、任务编排或新的后端接口。
- 不部署生产；推送和部署必须取得用户单独授权。

## 证据与判断

### 已确认事实

- 用户明确要求继承 `main` 主分支第一版 Electron 前端及其完全一致的动画效果。
- 当前 V2 在提交 `e059d10` 中重新设计了普通聊天壳，只复用了部分粒子组件，没有继承第一版完整视觉层。
- 当前回复期间每 100 毫秒生成模拟信号并随机触发 `tokenPulse`，这是粒子连续闪动的已确认根因。
- 当前 `ParticleCore` 场景只初始化一个动画循环，未发现因流式文本导致的反复挂载。
- 当前生产提交与仓库 `apps/mobile-web` 前端一致，样式差异不是部署漂移。
- 2026-08-14 用户验收指出输入区交互仍不符合第一版：当前实现默认展开，第一版桌面端应在鼠标进入底部热区时弹出，手机端应只显示小横条并在点击后弹出。
- 仓库存在 `runtime-images.yml` 流水线：推送 `v2` 且命中应用路径后会检查并发布固定提交镜像，但不会自动切换生产 VPS。

### 合理推断

- 完整照搬 Electron 页面会带入桌面端专属交互，因此应继承视觉结构和动画实现，并把业务事件适配到 V2 现有公开接口。
- 移动设备的可视区域和图形能力不同，需要保留性能分级和窄屏布局，才能达到视觉等价而非像素尺寸机械复制。

### 假设与开放问题

- 本次将“跟第一版一模一样”解释为视觉语言、粒子形态、动画节奏和状态反馈一致；桌面端专属侧栏与工作台不作为手机 Web 功能恢复。
- 生产真机上的最终手感仍需用户在发布后验收；本地验证只能覆盖等价移动视口和代码行为。

## 用户批准的方案

2026-08-14，用户明确批准在 V2 中继承 `main` 主分支第一版 Electron 前端，要求保留其长期打磨的动画和前端效果。本任务按“视觉层完整继承、V2 业务层不回退”的范围执行；生产推送与部署仍未授权。
