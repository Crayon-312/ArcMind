## 目标

在保留 ArcMind V2 现有文档分类和正文事实的前提下，把当前“目录化文件集合”修正为人类与 Agent（智能协作助手）都能沿关系追踪的知识网络，让 Obsidian（本地 Markdown 知识库工具）关系图呈现稳定的领域分组和跨领域主链。

## 非目标

- 不改写已经确认的产品、业务或架构结论。
- 不为了图形密度创建没有语义的链接。
- 不引入 Obsidian 社区插件、数据库、后台索引或专有格式。
- 不创建新分支或 Git worktree（Git 独立工作树），不推送远端。

## 基线证据

- 修正前共有 57 个 Markdown（轻量标记文档）文件。
- Obsidian 可识别的文档间链接只有 8 条，其中 7 条来自知识库首页。
- 49 个文档完全孤立，共形成 50 个连通分量，最大连通分量只有 8 个文档。
- 正文中已有 104 次反引号包裹的 `.md` 路径引用，说明内容关系存在，但没有被表达为可导航链接。
- 现有项目门禁只检查链接目标是否存在，不检查当前有效文档是否孤立。

## 用户批准的方案

- 用户确认关系图缺乏关联后，明确要求开始修正。
- 保留现有目录作为分类层，增加领域内容地图作为导航层。
- 用有含义的 Markdown 链接表达依据、实现、约束、发布和验收关系。
- 增加自动孤立文档检查，防止后续继续产生散点文档。

## 工作区模式

本任务继续在当前 `v2` 工作区串行执行。任务开始时工作区干净，只有本任务修改知识文档和检查脚本；没有并行任务、独立运行态或实验环境需求，因此新工作树不能带来额外稳定性收益。

## 关系设计原则

- 分类关系：总索引只连接领域内容地图，领域地图负责连接本域文档。
- 语义关系：正文只添加可以说明“依据、细化、实现、约束、发布或验收”的链接。
- 历史关系：方案台账和决策进入网络，但不替代当前正式事实。
- 可移植性：使用标准 Markdown 链接，不依赖 Obsidian 专有插件。
- 可验证性：正式状态文档必须至少具有一条可识别的内部文档关系。
