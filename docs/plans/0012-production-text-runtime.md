## 目标与边界

### 业务目标

把已经公开运行的“测试邮件 + 确定性回复”纵向切片推进为可长期维护的本人生产文字闭环：先建立服务器访问安全、证书检查和数据库备份恢复入口，再接入真实 SMTP（简单邮件传输协议）与 DeepSeek（深度求索模型服务），最后完成真实手机验收。

### 本次包含

- 为用户长期 SSH（安全外壳协议）密钥、密码轮换和关闭密码登录定义安全顺序；家庭电脑密钥未验证前不关闭密码登录。
- 增加短期公网证书剩余时间检查，低于 48 小时返回失败状态。
- 增加每日 PostgreSQL（关系型数据库）自定义格式备份、权限收紧、结构校验和本机保留入口。
- 扩展 SMTP 认证、STARTTLS（显式传输层安全升级）和 SMTPS（隐式加密邮件传输）配置。
- 增加可注入、可测试的 DeepSeek 非流式客户端和稳定错误分类，为后续耐久生成执行器复用。
- 在外部凭据具备后完成真实邮件、模型与手机验收。

### 本次不包含

- 不把凭据、服务器私钥、验证码、真实邮件正文或模型密钥写入 Git。
- 不在没有用户长期 SSH 密钥的设备验证前关闭服务器密码登录。
- 不用进程内后台任务代替耐久任务队列，不把完整回复后的事件回放描述为真实流式生成或取消。
- 不在没有对象存储和通知通道凭据时伪造异地备份或外部告警已上线。
- 不接触旧共享 VPS 或其任何项目、端口、容器、证书和数据。
- 不在本任务扩展语音、任务中心、记忆或工作机执行链路。

## 证据与判断

### 已确认事实

- 用户已批准按“访问安全 → 运维底座 → 真实 SMTP → 真实 DeepSeek → 真实手机”的顺序推进，并要求保持最小正确实现。
- 新 VPS 是 ArcMind 独立服务器；当前公网身份、文字事件回放、刷新恢复与退出链路已经验收。
- 当前 `TestMailAdapter` 只支持无认证 SMTP；`DeterministicModelProvider` 只产生测试文本。
- `createTextTurn` 当前在 HTTP（超文本传输协议）请求和数据库事务内等待模型生成完成，之后 SSE（服务器发送事件）只回放已持久化事件。
- 当前没有生产 SMTP、DeepSeek、异地对象存储、外部告警和用户家庭电脑 SSH 公钥凭据。

### 合理推断

- SMTP 传输安全和认证可以在现有适配器边界内局部实现，不需要新增框架。
- 证书检查与逻辑备份适合先做成可审查脚本，由定时器和外部告警通道调用；非零退出可形成稳定的监控集成点。
- 真实流式生成必须脱离当前请求事务并具备进程重启后的明确状态；已有 PostgreSQL-backed Procrastinate（基于 PostgreSQL 的耐久任务队列）决策比进程内任务更符合稳定性要求。

### 假设与开放问题

- 异地备份优先使用腾讯云 COS（对象存储服务），但存储桶、地域、最小权限凭据和保留规则尚未提供。
- 告警接收通道尚未确定；在确认前，检查脚本只提供退出码和不含凭据的诊断输出。
- DeepSeek 生产模型名、账户可用区、余额、真实 API 行为和固定用例质量仍需部署密钥实测。
- 首轮真实模型是否允许临时采用非流式完整回复尚未授权；默认继续以耐久流式实现作为生产启用前置条件。
