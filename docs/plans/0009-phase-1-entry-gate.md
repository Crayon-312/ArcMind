## 目标与边界

### 业务目标

关闭第一阶段设计就绪门禁中的 DR-004 至 DR-007，为三应用工程骨架和第一条身份纵向切片提供足够明确、可验证且不过度扩展的设计依据。

### 本次包含

- 定稿“本人优先”的邮箱验证码身份、会话、恢复、撤销和最低限速规则。
- 验证固定公网 IP（互联网协议地址）直接提供可信 HTTPS（安全超文本传输协议）的可行性和恢复方式。
- 定稿文字增量响应、任务进度和重连所需的 SSE（服务器发送事件）通道与错误语义。
- 选择首个主 Agent（智能任务编排助手）模型供应商和最小失败降级方式。
- 将身份、事件和错误契约转换为 OpenAPI（开放接口描述规范）3.1 与 JSON Schema（JSON 数据结构规范）。
- 补齐身份与文字闭环的页面状态和测试矩阵，重新判定第一阶段门禁。

### 本次不包含

- 不创建三应用工程骨架或业务代码。
- 不实现实时语音、工作机连接、长期记忆、提醒或公开注册体系。
- 不设计组织、角色、多租户、管理员后台或复杂账号治理。
- 不把尚未在目标 VPS（虚拟专用服务器）和真实手机验证的部署行为写成当前已实现事实。
- 不因“仅本人使用”取消会话保护、验证码一次性消费、限速或审计基线。

## 证据与判断

### 已确认事实

- 用户确认首版只保障本人使用，但保留普通个人账户边界；不做组织、角色、多租户和公开注册治理。
- 用户确认使用邮箱短时一次性验证码，不使用密码作为首版登录凭据。
- 用户当前没有域名，希望优先使用“可信 HTTPS + 公网 IP”访问。
- Let’s Encrypt（免费公开证书颁发机构）于 2026-01-15 宣布 IP 地址证书正式可用，支持 IPv4 和 IPv6，证书有效期为 160 小时；IP 地址证书必须使用 `shortlived`（短期证书）配置档。
- Let’s Encrypt 对 IP 地址只支持 `http-01` 或 `tls-alpn-01` 两种 ACME（自动证书管理环境）所有权校验，不支持依赖域名系统的 `dns-01`。
- Caddy（自动 HTTPS 反向代理）当前稳定版 v2.11.4 暴露 ACME `profile` 配置，并允许 Let’s Encrypt 签发公网 IP 证书；IP 地址仍需显式配置公开证书签发器，不能依赖默认的本地自签名行为。
- 浏览器中的麦克风等强能力要求安全上下文；远程资源通常必须通过浏览器认可的 HTTPS 提供。安全 Cookie（浏览器会话凭据）可在 HTTPS 下使用，省略 `Domain` 属性时形成仅当前主机可用的 Cookie。
- 当前尚未提供目标 VPS、公网 IP、端口可达性或真实手机验证结果，因此 DR-005 还不能标记为通过。

### 合理推断

- 若目标 VPS 具有长期稳定、直接可达的公网 IPv4，且 80/443 端口可由 Caddy 独占，则“公网 IP + Let’s Encrypt 短期证书 + Caddy 自动续期”可以作为首版最小部署路径。
- 该路径不需要购买域名，但证书只有 160 小时，续期、证书存储持久化和到期监控属于可用性硬要求；其运维容错低于普通域名证书。
- 手机 Web 与 API（应用程序接口）保持同源部署，可避免跨域会话配置，并允许使用不带 `Domain` 的 `__Host-` 前缀 Cookie。
- 本人优先最简单的注册边界是部署配置中只允许一个归一化邮箱；接口仍保持普通个人用户与多会话模型，未来增加用户不需要重写身份主体。

### 假设与开放问题

- 目标 VPS 是否提供不会随重启变化的固定公网 IPv4，80/443 是否能被公网验证节点直接访问。
- 目标网络是否存在运营商 NAT（网络地址转换）、云防火墙、端口转发或代理层，导致证书校验实际落到其他主机。
- 生产邮件通过哪一个 SMTP（简单邮件传输协议）中继发送；仓库只定义标准适配器，不保存真实账号和密钥。
- 首个主 Agent 模型供应商、具体模型、部署地区、凭据和可接受成本尚未选择。
- 如果公网 IP 证书签发、自动续期或真机兼容验收失败，可信主机名替代路径需由用户另行确认，不在本草稿中预选第三方隧道。

## 待确认的最小方案

### 身份与会话

- 只允许部署配置中的一个归一化邮箱发起验证码；对外响应不暴露邮箱是否被允许或已存在。
- 验证码为 6 位数字、10 分钟过期、最多失败 5 次、成功后立即消费；同一邮箱签发新挑战时使旧挑战失效，服务端只保存验证码摘要。
- 发送限速初值：同一邮箱 15 分钟最多 3 次，同一来源 IP 15 分钟最多 10 次；验证失败受挑战次数和来源 IP 双重限制。数值通过配置调整，但生产环境不得关闭。
- 登录成功后签发至少 256 位随机会话令牌；数据库只保存令牌摘要。Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/`，名称使用 `__Host-arcmind_session`，不设置 `Domain`。
- 会话允许本人多个浏览器同时在线；空闲 7 天失效、绝对 30 天失效。支持退出当前会话和撤销全部会话，撤销同时终止对应 SSE 长连接。
- 首版身份恢复等同于重新通过邮箱验证码登录；邮箱本身失去控制时不提供绕过邮箱的后门恢复。重新登录后提供“撤销全部其他会话”。
- 手机 Web 与 API 同源部署，并对改变状态的请求校验 `Origin`（请求来源）和幂等标识；不开放任意跨域携带会话凭据。
- 开发环境使用邮件捕获器或测试适配器；生产环境使用标准 SMTP 适配器和外部中继，真实凭据只进入部署环境。

### 公网 IP 与 HTTPS

- 首版只承诺一个固定公网 IPv4；IPv6 仅在目标 VPS 确实提供稳定地址并单独通过验证后启用。
- 反向代理锁定到 Caddy v2.11.4 或经验证的更高兼容版本，显式选择 Let’s Encrypt ACME 服务和 `shortlived` 配置档。
- 公网只暴露 80/443；应用、数据库和内部管理端口不直接暴露。Caddy 证书、账户和续期状态使用持久卷保存。
- 部署验收必须覆盖：生产证书链可信、IP 地址匹配、HTTP 自动跳转 HTTPS、手机浏览器无证书警告、`isSecureContext` 为真、Secure Cookie 正常、麦克风权限可请求。
- 续期验收必须覆盖：重启后证书状态保留、短期证书进入自动续期窗口、续期失败可观察、剩余有效期低于 48 小时时告警。
- 任一硬条件失败时不得退化到忽略证书警告或明文 HTTP；任务回到 `confirmed` 状态，由用户选择可信主机名替代路径。

### 文本事件与模型

- 文字请求使用普通 HTTPS 创建用户轮次和响应记录，增量输出通过经 Cookie 鉴权的 SSE 返回；最终轮次必须持久化，SSE 不是事实源。
- 每个事件包含稳定事件 ID、事件类型、会话 ID、响应 ID、序号和时间；客户端使用 `Last-Event-ID` 或显式游标重连，重复事件按 ID 去重。
- 首版事件至少覆盖 `response.started`、`response.delta`、`response.completed`、`response.failed` 和心跳；任务阶段再复用同一事件信封增加任务进度类型。
- 断线后允许丢弃未持久化的历史增量，但必须能查询最终轮次；生成仍在进行时，重连从服务端保留的有限事件窗口继续，窗口外返回可识别的“重新同步”错误。
- 模型适配器只暴露生成、取消、超时、限流和供应商错误归一化；首个供应商失败时保存用户轮次和失败事实，允许用户重试，不在首版自动切换第二家模型造成重复计费或语义漂移。
- 首个供应商必须通过官方接口、目标网络连通、中文效果、流式取消、结构化输出、价格和数据路径核查后才能写入正式决策。
