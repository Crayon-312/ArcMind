## 为什么需要云端存储

手机 Web 页面可能被关闭，工作机也可能离线。如果会话、记忆和任务只保存在某一端，跨设备连续性、提醒和异步任务就无法可靠实现。因此云端保存业务事实，本地只保留可丢弃缓存和执行所需的最小材料。

## 核心数据对象

| 对象 | 含义 | 主要所有者 |
|---|---|---|
| User | 用户主体和偏好边界 | 身份服务 |
| Device | 手机会话或工作机设备关系 | 身份与工作机网关 |
| Conversation | 一次实时或文字会话 | 会话服务 |
| Turn | 用户或 AI 的一个对话轮次 | 会话服务 |
| Memory | 经筛选的跨会话稳定事实 | 记忆服务 |
| Task | 用户确认后的工作目标 | 任务编排器 |
| TaskStep | 可执行、可跟踪的任务步骤 | 任务编排器 |
| Approval | 某项高风险动作的限定确认 | 任务编排器 |
| Execution | 云端工具或工作机上的一次执行尝试 | 执行网关 |
| Event | 会话、任务、设备或提醒的状态变化 | 对应领域模块 |
| Reminder | 定时触发的提醒规则 | 提醒服务 |
| Artifact | 结果产物的元数据和受控引用 | 任务编排器/对象存储 |

## 上下文与长期记忆的区别

- 原始轮次用于短期连续对话，不自动成为长期记忆。
- 会话摘要压缩当前讨论，保留目标、约束、决策和开放问题。
- 长期记忆只保存未来可能复用且用户允许保留的稳定事实。
- 任务记录保存执行事实，即使相关会话已被清理也要保持状态一致性。
- 用户偏好可以影响交互，但不能越过安全和审批规则。

## 记忆写入流程

1. 从对话中识别候选事实。
2. 判断是否稳定、必要、允许长期保存。
3. 去重并检查与现有记忆是否冲突。
4. 保存摘要、来源、可信度和有效状态。
5. 在后续对话中按范围检索，而不是把全部记忆注入模型。
6. 用户更正时保留变更关系并停止使用旧事实。

## 数据生命周期要求

- 为原始音频、转写、会话、任务、产物和日志分别定义保留期。
- 原始音频默认不应长期保存；需要保存时必须有明确目的和用户控制。
- 用户可以查看、更正和删除长期记忆。
- 删除用户数据时需处理数据库、对象存储、检索索引和异步队列中的副本。
- 诊断日志优先记录标识、耗时、状态和错误分类，减少记录对话正文。
- 备份策略必须与删除承诺和恢复目标一致。

## 一致性原则

- 任务状态以任务编排器为准，工作机日志只是证据来源。
- 会话文本与模型生成音频通过稳定响应标识关联。
- 同一状态事件重复到达不得造成重复执行。
- 异步处理采用事件时间和服务端版本控制，不依赖客户端时钟。
- 检索索引可以重建，不能成为唯一数据源。

## 已确认存储基线

- PostgreSQL 18 是云端唯一主事实库。
- SQLAlchemy 2.0 负责数据库映射，psycopg 3 提供 PostgreSQL 驱动，Alembic 管理版本化迁移。
- 记忆的结构化事实保存在普通关系表中；pgvector 仅保存与记忆版本关联的可重建向量。
- 最终对话轮次、任务状态和提醒实例进入主数据库；实时音频片段和临时转写默认不持久化。
- 二进制产物与未来需要保留的音频不直接写入 PostgreSQL，只保存元数据和对象存储引用。
- 业务写入与跨模块事件使用 Transactional Outbox（事务发件箱）保证同一事务提交；外部回调使用 Inbox（收件箱）或幂等记录去重。

详细表组、事务边界和备份要求见[数据存储、事务与检索设计](11-data-storage-and-transactions.md)。

## 待定设计

- 各类数据默认保留期和用户可配置范围。
- 长期记忆的自动写入阈值与人工确认策略。
- 二进制产物使用的 S3 兼容对象存储产品。
- 跨地域备份与灾难恢复目标。
