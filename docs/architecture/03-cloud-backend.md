## 定位

云端后端是 ArcMind V2 的连续业务中枢。它不是单纯的手机与工作机转发代理，而是维护身份、对话上下文、长期记忆、任务状态、提醒和设备连接的唯一协调层。

## 逻辑模块

| 模块 | 职责 | 关键输出 |
|---|---|---|
| 身份与访问 | 注册、登录、会话生命周期、设备绑定和访问控制 | 用户主体、访问会话、设备关系 |
| 会话服务 | 创建实时或文字会话，聚合转写和消息 | 会话记录、轮次、实时状态 |
| 实时语音网关 | 隔离供应商连接、音频事件和打断差异 | 标准实时事件、用量、错误分类 |
| 主 Agent Runtime | 理解目标、调用记忆、提出方案、拆解任务和请求确认 | 回复、任务草稿、工具请求 |
| 任务编排 | 管理任务、步骤、依赖、路由、租约、审批和状态 | 任务事实、执行命令、进度事件 |
| 记忆服务 | 管理短期上下文、长期事实、偏好和检索 | 受控记忆片段、来源和有效性 |
| 提醒与通知 | 管理计划时间、触发、投递和已读状态 | 提醒事件、消息记录 |
| 工作机网关 | 接收工作机出站连接、维护在线状态和转发任务 | 设备状态、任务投递与回执 |
| 耐久 Job Runtime | 运行 Outbox 投递、短后台工作、重试、提醒扫描和异常协调 | 内部 Job 结果、重试与运维状态 |
| 可观察性 | 关联请求、会话、任务、设备和供应商事件 | 指标、结构化日志和诊断线索 |

逻辑模块不等于首版必须拆成多个微服务。初期可以采用模块化单体，但公开边界和数据所有权不得省略。

## 数据所有权

- 会话服务拥有会话和轮次元数据。
- 任务编排拥有任务、步骤、状态和审批事实。
- 记忆服务拥有长期记忆及其来源、有效期和更正记录。
- 工作机网关拥有设备在线状态和连接租约，不拥有任务业务状态。
- 实时语音网关拥有供应商会话映射和瞬时媒体状态，不拥有长期用户事实。

## 对外接口类型

- 请求响应 API（应用程序接口）：身份、列表、详情、设置和确认操作。
- 实时事件通道：会话状态、文本增量、任务进度、审批和消息。
- 媒体通道：浏览器与语音供应商之间的音频流和控制事件。
- 工作机通道：能力注册、心跳、任务租约、进度、结果和取消。

## 关键规则

- 接受用户输入不等于获得执行授权。
- 主 Agent 的自然语言输出不直接修改任务状态；必须调用任务编排公开接口。
- 任务派发必须记录目标、版本、幂等键和授权上下文。
- 对话、任务和通知可以异步推进，不能依赖手机页面持续在线。
- 供应商回调和工作机事件默认不可信，必须验证来源、顺序和重复投递。
- 长任务应使用持久化队列或等价机制，不依赖单个 Web 请求生命周期。
- 首版持久化队列使用 Procrastinate + PostgreSQL；队列记录不能成为用户任务、提醒或通知的事实源。
- 首个文字响应切片使用同一个 PostgreSQL 事务写入用户轮次、响应记录和 Procrastinate Job，避免“领域记录已提交但后台作业未入队”的双写缺口；这个直接入队边界只适用于复用同一数据库连接的内部模型 Job。
- 工作机长任务只通过短 Job 完成派发和协调，接收回执后释放云端 Worker，由执行租约和事件继续跟踪。

## 部署原则

- 首版可以部署在一台 VPS（虚拟专用服务器）的多个容器中，但逻辑职责必须保持清晰。
- 主事实库使用独立 PostgreSQL 18 容器；Procrastinate 复用该数据库服务但使用组件自有表和独立连接池，对象存储仍待对应阶段确认。
- API、Worker、Outbox Dispatcher（发件箱投递器）、Reminder Scheduler（提醒调度器）和 Reconciler（协调恢复器）必须能够独立启动、健康检查和重启。
- 任何公网入口必须使用可信 HTTPS；内部组件优先使用私有网络和最小暴露端口。
- 备份、迁移和恢复能力要在承载真实长期记忆前完成设计。
