## 定位

工作机端是 ArcMind V2 的可选执行扩展。它安装在用户自己的工作电脑上，让云端主 Agent 在用户授权范围内调用本地工具、文件和开发环境。它不是云端后端的替代品，也不是新的通用编程 Agent。

正式名称使用“工作机客户端”或 `workstation-client`。它包含安装、升级、常驻连接和任务执行能力；“工作机安装端”只描述交付动作，不能覆盖完整运行职责。

## 内部组成

| 子组件 | 职责 |
|---|---|
| 安装与升级 | 安装、卸载、签名校验、版本升级和失败回滚 |
| 本地服务 | 启动、单实例、系统生命周期和本地设置 |
| 云端连接 | 出站长连接、重连、心跳、协议协商和设备状态 |
| 权限控制 | 工作区授权、高风险动作确认和本地策略 |
| 执行器宿主 | 调用 Codex CLI 等工具，隔离输入、进度和结果 |
| 本地观察界面 | 展示连接、任务、审批和诊断，不承担云端全局管理 |

## 职责

- 与用户身份和指定设备建立绑定关系。
- 主动向云端发起加密长连接，避免要求工作机具有公网 IP 或开放入站端口。
- 注册设备能力，例如编程执行、文档处理或特定自定义工作流。
- 接收有范围、有效期和幂等标识的任务包。
- 根据本地策略接受、拒绝或等待用户确认。
- 调用 Codex CLI 等现有执行工具，并隔离各工具的输入输出差异。
- 回传真实进度、结构化结果、产物引用、失败原因和可恢复状态。
- 在断线、重启或用户取消后安全恢复或终止任务。

## 不负责

- 不维护全局会话、长期记忆或任务唯一事实。
- 不把任意自然语言直接转成不受限系统命令。
- 不允许云端绕过本地策略访问整台电脑。
- 不将执行工具的完整内部日志默认上传云端。
- 不因为“同一用户”而永久授权所有未来动作。

## 连接模型

```text
工作机启动
  -> 本地身份确认
  -> 主动连接云端
  -> 注册能力与版本
  -> 心跳保持在线
  -> 获取任务租约
  -> 本地审批与执行
  -> 回传进度/结果
  -> 完成、续租或释放
```

工作机离线时，云端保留任务并显示等待状态；不得将未送达任务标记为执行中。

## 执行器适配边界

每个执行器至少暴露：

- `capabilities`：支持的任务类型和约束。
- `prepare`：验证环境、输入和权限。
- `execute`：开始执行并返回稳定执行标识。
- `observe`：获取进度和结构化事件。
- `cancel`：请求安全停止。
- `collect`：收集结果和允许回传的产物引用。

首个执行器应选择范围窄、容易验证的能力，待任务租约、审批和回传闭环稳定后再接入更多工具。

## 权限模型

- 能力级允许：设备是否允许某类工作。
- 工作区级允许：执行器可以访问哪些目录或项目。
- 动作级确认：删除、覆盖、发布、外发等动作单独确认。
- 时间级有效：批准具有明确有效期，不永久扩大权限。
- 结果级过滤：只回传必要摘要和明确产物，不默认上传本地全部内容。

## 多设备规则

- 每台工作机具有独立设备标识、能力清单和在线状态。
- 默认不同时将同一非幂等任务派发给多台设备。
- 用户可以指定设备；未指定时由编排器按能力、在线和策略选择。
- 设备更名、解绑和失效不能改变历史任务归属。
