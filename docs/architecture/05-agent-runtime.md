## 名称边界

本文的 Agent Runtime（智能协作助手运行时）属于 ArcMind 产品。它与用于开发仓库的 Agent Context OS 没有运行时依赖关系。

## 核心角色

| 角色 | 主要职责 | 禁止越界 |
|---|---|---|
| 贾斯汀交互层 | 实时听说、澄清、复述、播报和呈现状态 | 不伪造任务状态，不直接获得本地无限权限 |
| 主 Agent | 理解意图、读取上下文、形成方案、拆解任务、选择能力和请求确认 | 不绕过任务编排直接宣称执行完成 |
| 任务编排器 | 保存任务事实、依赖、状态、审批、派发和重试 | 不代替模型讨论方案，不直接操作本地文件 |
| 云端工具 | 执行只需要云端资源的受控动作 | 不访问未授权工作机资源 |
| 工作机执行器 | 调用本地工具完成指定任务步骤 | 不扩展任务范围，不维护全局记忆 |
| 记忆服务 | 提供相关上下文并写入经过筛选的稳定事实 | 不把每段原始对话自动永久化 |

## “边聊边干活”的两类执行方式

主 Agent 在任务确认后根据任务类型选择：

1. 直接调用受控工具：适合单步、低风险、输入输出明确的动作，例如查询任务状态或创建提醒。
2. 创建执行任务：适合多步骤、长时间、需要本地环境或需要专门执行 Agent 的工作，例如编程、文档生成和复杂调查。

这两种方式不是二选一的全局架构。一个计划可以先由主 Agent 拆解，再让部分步骤调用云端工具，部分步骤派发给工作机中的 Codex CLI 或其他执行器。

## 任务形成流程

```text
用户表达意图
  -> 贾斯汀进行实时澄清
  -> 主 Agent 检索相关上下文
  -> 形成目标、约束、步骤和验收草稿
  -> 用户确认
  -> 任务编排器创建可执行任务
  -> 云端工具或工作机执行器执行
  -> 任务事件回传
  -> 贾斯汀查询事实并反馈用户
```

## 实时语音模型的角色

实时语音模型可以同时完成语音识别、语言理解和语音生成，但系统设计不能假设它天然拥有完整业务上下文和所有工具能力。推荐将它定位为低延迟对话协作者：

- 快速处理轮次、打断和自然口语。
- 将稳定转写、用户确认和结构化意图交给主 Agent。
- 从云端获得任务真实状态后再播报。
- 供应商支持函数调用时可以用于低风险会话控制，但仍需经过云端策略层。

## 首个主 Agent 模型适配

- 首个接入使用 DeepSeek `deepseek-v4-pro`，通过 ArcMind `ModelProvider` 端口进入 LangGraph。
- 供应商流式增量先归一化为 ArcMind 响应事件；公开契约和领域状态不保存供应商私有事件结构。
- 工具调用只形成参数提议，必须经过本地 Schema（数据结构规范）、权限和任务状态校验后才能执行。
- 供应商故障保留用户轮次和失败事实，由用户决定重试；首版不自动切换第二家模型。

## 主 Agent 与子 Agent

- 主 Agent 负责用户目标一致性和最终计划。
- 子 Agent 或专用执行 Agent 是可选执行资源，由任务类型决定，不要求每个步骤都创建。
- 子 Agent 的自然语言结论不是任务完成证据；编排器需要验证结果并更新步骤状态。
- 子 Agent 不直接拥有用户完整长期记忆，只获取当前任务必要上下文。

## 上下文分层

- 实时窗口：当前通话最近轮次和打断状态。
- 会话摘要：本次对话已确认目标、约束和待确认点。
- 用户记忆：跨会话稳定偏好与事实，按需检索。
- 任务上下文：目标、计划、步骤、产物和执行事件。
- 执行上下文：单个执行器完成当前步骤所需的最小材料。

## 可靠性规则

- 模型回复和任务状态分离。
- 所有有副作用的工具调用必须具有明确调用记录。
- 长任务由持久化编排驱动，不依赖模型会话持续存在。
- 用户修改目标时创建可追踪的计划版本，不静默覆盖正在执行的范围。
- 主 Agent 查询不到真实进度时必须说明未知，不能根据时间估算伪造状态。
