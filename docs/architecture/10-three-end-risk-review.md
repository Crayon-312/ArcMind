# 三端架构一致性与风险审查

状态：current
最后校验日期：2026-07-30

## 审查结论

手机 Web、云端后端和可选工作机客户端的总体方向成立，职责划分没有根本冲突。仓库组织、首阶段运行时、数据库和耐久 Job 技术栈已经定案；当前阻塞重点收敛为身份、HTTPS、实时事件、模型接入和可执行契约。

## 已确认且合理的部分

- 云端是持续业务中枢，手机与工作机都连接云端。
- 手机 Web 是主要交互入口，不承担长期后台任务。
- 工作机客户端是可选执行扩展，不要求公网 IP。
- 实时语音层不拥有任务和长期记忆事实。
- 工作机通过受控执行器调用 Codex CLI 等工具，而不是重写编程 Agent。
- 三端通过公开契约通信，不直接依赖彼此内部实现。

## 发现的问题与修正

| 编号 | 问题 | 风险 | 修正建议 | 状态 |
|---|---|---|---|---|
| AR-001 | “三个项目”可能被理解为三个 Git 仓库 | 提前增加契约同步和联调成本 | 采用单仓库三应用 | resolved |
| AR-002 | “工作机安装端”只描述安装动作 | 容易遗漏常驻连接、权限、升级和执行器职责 | 统一命名为工作机客户端，安装器作为子组件 | resolved |
| AR-003 | P0 实时语音与“先做文字闭环”看似冲突 | 可能误以为第一批代码必须先接语音 | P0 表示首版产品必需，不表示第一开发顺序 | resolved |
| AR-004 | 完整后端做完再做手机端 | API 与真实交互脱节，返工集中爆发 | 云端基础先行，随后按纵向切片联调 | resolved |
| AR-005 | 云端内部模块过多 | 初期拆微服务造成运维负担 | 首版采用模块化单体，保持逻辑边界 | proposed |
| AR-006 | 公开 API 和事件契约仍为 Markdown 草案 | 无法自动检测跨端兼容 | 编码前转成机器可校验 Schema | open |
| AR-007 | 邮箱注册已确认但登录机制未定 | 身份代码容易重写 | 技术选型阶段先定登录、恢复和撤销 | open |
| AR-008 | HTTPS 可信方案未定 | 手机麦克风、实时连接和推送可能不可用 | 在身份纵向切片前完成真机验证 | open |
| AR-009 | 工作机协议和安全边界复杂 | 过早开发会阻塞核心手机体验 | 工作机排在文字、任务和实时语音闭环之后 | resolved |
| AR-010 | 实时语音媒体路径未定 | 浏览器直连与云端代理影响延迟和安全 | 供应商评测时做两种链路原型 | open |
| AR-011 | 三端可能采用不同语言 | 直接共享源码包会形成隐性耦合 | 共享 Schema 并生成各端类型 | resolved |
| AR-012 | 云端成为单点 | 故障影响全部端 | PostgreSQL 每日异地备份并定期恢复演练；应用建立健康检查 | controlled |
| AR-013 | LangGraph 运行态与业务任务表形成双重事实 | 恢复后任务状态冲突或重复执行 | LangGraph 只保存图运行态，业务变更必须经领域服务 | controlled |
| AR-014 | Electron 权限放大浏览器漏洞影响 | 工作机文件或命令能力被越权调用 | 本地页面、隔离渲染器、白名单 IPC 和能力审批 | controlled |
| AR-015 | 队列 Job、用户任务和工作机长执行可能形成三套互相覆盖的状态 | 重复执行、错误进度或重启后状态漂移 | 采用 Procrastinate 适配层；`Task`、`ExecutionLease` 和提醒实例继续由领域表维护 | controlled |

## 当前阻塞级问题

开始正式业务代码前至少需要确认：

1. 邮箱登录与身份恢复方式。
2. 可信 HTTPS 和本地开发证书方案。
3. 实时事件通道与错误模型。
4. 把 OpenAPI 与事件 JSON Schema 从决策转换为机器可校验文件。
5. 主 Agent 首个模型供应商与失败降级策略。

实时语音供应商不阻塞第一条文字纵向切片，可以后续定案。工作机 MVP 技术方向已经确定为 Electron + TypeScript，但工作机功能仍按实施顺序后置。

耐久 Job 与提醒调度已由决策 0009 定案，不再是代码骨架前的开放选型；正式 Worker 实现前仍必须完成隔离技术验证和重复投递故障注入。

## 不建议的做法

- 一次性搭完所有云端模块后才做第一个页面。
- 先做视觉完整的手机页面，再用模拟数据长期代替真实 API。
- 第一阶段同时开发实时语音、长期记忆、提醒和工作机执行。
- 因为处于单仓库就直接导入另一个应用内部代码。
- 在身份、HTTPS 和数据迁移未明确前上线保存真实对话。
