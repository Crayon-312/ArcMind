## 总体拓扑

```text
手机 Web 端
  ├─ 实时音频与界面状态 ──────────────┐
  ├─ 任务确认、进度查询与消息 ────────┤
  └─ 用户输入                         │
                                     v
                              ArcMind 云端后端
                              ├─ 身份与会话
                              ├─ 实时语音网关
                              ├─ 主 Agent 与任务编排
                              ├─ 记忆、任务与提醒
                              └─ 设备连接与事件中继
                                     │
                         安全的工作机出站长连接
                                     v
                              可选工作机端
                              ├─ 能力与权限管理
                              ├─ 本地执行器适配
                              └─ 进度与结果回传
```

## 组件职责

| 组件 | 负责 | 不负责 |
|---|---|---|
| 手机 Web 端 | 采集与播放音频、呈现会话状态、任务确认、进度和消息 | 长期事实存储、复杂任务编排、直接控制工作机 |
| 云端后端 | 连续身份、上下文和记忆、主 Agent、任务状态、提醒、跨端路由 | 未经授权读取本地资源、假装工作机执行成功 |
| 实时语音供应商 | 低延迟音频理解与生成、会话级对话控制 | 成为任务唯一事实源、永久保存业务状态、直接拥有本地执行权限 |
| 工作机端 | 注册本地能力、执行授权任务、回传真实进度和产物 | 维护全局用户记忆、替代云端任务表、接受任意未验证指令 |
| Agent Context OS | 约束开发工具读取上下文、实施和验收仓库变更 | 参与 ArcMind 用户会话或产品任务执行 |

## 三套可部署应用

逻辑架构最终对应三块独立代码：

```text
mobile-web
  -> 面向手机浏览器的交互应用

cloud-server
  -> 面向公网和内部任务的持续云端服务

workstation-client
  -> 安装在用户工作电脑上的可选执行客户端
```

三者必须能够独立构建、测试、发布和回滚。它们是否位于同一 Git 仓库属于工程组织决策，不改变三端产品边界。

## 两条数据路径

### 实时媒体路径

承载用户音频、模型生成音频、打断和实时状态。该路径追求低延迟，可以由手机端直连供应商或经云端代理，具体模式在供应商选型时决定。

无论媒体是否直连供应商，云端都必须获得受控的文本事件或结构化意图，才能维护业务上下文和任务事实。

### 控制与任务路径

所有任务确认、拆解、派发、审批、状态变化和结果都经过云端。工作机只通过出站连接接收已签发的任务包，并将状态事件回传云端。

## 核心架构规则

1. 云端是跨会话和跨设备的业务事实中枢。
2. 工作机是可选执行节点，不是手机端的必需依赖。
3. 手机端不得直接远程调用工作机本地工具。
4. 实时语音层和主 Agent 层通过稳定的会话事件接口解耦。
5. 主 Agent 生成计划和路由决策；具体执行由云端工具或工作机执行器完成。
6. 任务表而非自然语言回复代表真实执行状态。
7. 每个跨端命令必须可追踪、可去重并有明确的授权范围。

## 故障隔离

| 故障 | 应保留能力 |
|---|---|
| 实时语音供应商不可用 | 文字聊天、任务查询和已有提醒继续工作 |
| 工作机离线 | 云端聊天、记忆和提醒继续工作；本地任务等待或改派 |
| 手机离线 | 云端和已开始的工作机任务按策略继续；重连后查询状态 |
| 主 Agent 暂时不可用 | 已存在任务状态不丢失；禁止伪造新计划和进度 |
| 云端不可用 | 手机与工作机不得绕过云端私自扩大执行范围 |
