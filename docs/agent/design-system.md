# 界面风格规范

本文件定义 ArcMind 的长期界面风格。任何视觉、交互、动画、前端组件或粒子系统改动，都必须先阅读并遵守本规范。

## 风格命名

项目界面采用 **ArcMind Core Console** 风格，中文定位为 **弧核智能终端**。

它不是普通客服聊天框，不是营销型 landing page，也不是单纯炫技 HUD。它应该像一个本地 AI 终端：沉浸、克制、清晰、有回应感，让用户一眼感到 AI 正在聆听、思考或回答。

## 已选视觉基线

默认视觉方向采用 **深色粒子核心 + 精准隐式边缘交互 + 透明玻璃浮层 + 右侧 Markdown 工作台**。

- **粒子核心是识别点**：全屏 WebGL/Canvas 背景呈现弧形粒子、能量核心、声波脉冲和状态变化。
- **品牌图标统一**：正式图标采用用户已确认的 B 版全息弧核原图，只通过背景提取获得透明通道，保留原图的冰青多层能量环、明亮智能内核、细外环和极小暖金脉冲；窗口、任务栏、安装包、页面图标和左上角品牌锚点必须使用同一套资源。图标外围必须保留真实透明通道，禁止使用不透明黑色方块、深色底板、伪透明容器或重新生成的替代造型。
- **沉浸首屏是默认态**：首屏只保留 `ArcMind` 品牌锚点、弦核状态和必要隐藏拖拽区，不常驻聊天框、顶部条或密集 HUD。
- **内容可读是底线**：长回答、报告、代码、表格和选择项优先进入右侧工作台，输入、设置和错误反馈必须清晰可读，不被视觉层遮挡。
- **状态驱动优先**：待机、聆听、思考、回答、错误、静音必须有稳定且可区分的视觉表现。
- **透明玻璃浮层**：边缘抽屉、工具 rail、输入栏、设置、记忆和工作台使用深色半透明玻璃、背景模糊、内侧高光和弱青色边界；参考外部项目时只吸收交互气质和材质原则，不复制源码、滤镜图或资产。
- **克制电影感**：可以有扫描线、微光、粒子轨道和透明面板，但不能让界面变成噪声堆叠。

## 设计关键词

- **弧核**：环形、轨道、核心、脉冲是主要视觉语言。
- **私人助手**：语气温和、反馈及时、状态清楚。
- **沉浸但可控**：第一屏有氛围，但设置、历史和错误处理保持桌面软件的可靠性。
- **大众化体验优先**：隐藏式交互必须符合普通用户直觉，关键输入能力要容易被发现、容易唤出、不会误触，并且不能让用户担心内容丢失。
- **状态同步**：视觉层必须响应真实业务状态，不自行制造虚假进度。
- **隐私可信**：记忆、历史、麦克风、模型配置必须让用户知道在哪里、怎么关、怎么删。

## 布局规则

- 首屏直接呈现可唤起的聊天体验，不做营销 hero。
- 视觉层全屏铺底；会话、工具、工作台和输入层作为边缘浮层。
- 聊天历史不常驻覆盖弦核；长内容区域必须有足够对比度和可读宽度，不被粒子高亮干扰。
- 设置、历史、记忆管理优先使用侧栏、抽屉或独立面板，不打断主对话。
- HUD 信息层不再默认常驻；回应就绪、记忆、设置、播报等短状态放入右上角极小热区唤出的图标工具 rail。工具 rail 必须从右向左滑出，按钮保持图标化，点击后再从右侧弹出对应工作台、记忆或设置面板。
- 系统状态遥测只能作为弦核周边的次级态势信息：优先使用单个小型透明 3D 投影面板，避免多面板围绕核心抢占视觉焦点；该类面板不使用毛玻璃模糊，主要依靠透明材质、边缘高光、弱投影平面和透视变形形成立体感。
- 左上角使用极小不可见热区唤出会话抽屉，不显示常驻历史按钮；底部输入通过小型底部识别区 hover/focus 自动弹出，也可以点击把手兜底唤出，不使用大面积 hover 区；右侧工作台按报告、长回答或选择项自动弹出，但不抢走输入焦点。
- 所有隐藏控件识别区必须精确：右上工具和左上会话默认控制在角落小范围内，底部输入只响应把手区域，避免鼠标经过边缘时误触。
- 输入栏自动收起应尊重用户意图：没有草稿时，鼠标和键盘焦点离开后直接隐藏；已有草稿时应长时间保留，避免用户担心内容丢失。输入栏顶部中间应提供小型向下箭头用于手动收起，点击只隐藏输入栏，不清理文本；录音/转写等进行中状态不得被强行藏掉。
- 右侧工作台使用 Markdown 作为默认呈现方式，必须支持标题、列表、表格、代码块和链接；选择项应转成按钮列表并回到现有对话流程。流式回复必须经过本地 typewriter reveal 队列平滑显示，不能因为供应商大段 flush 而整段弹出。
- 固定格式元素必须有稳定尺寸，流式文字、状态标签和按钮变化不得造成明显布局跳动。
- 滚动容器必须统一定制滚动条样式，避免回退到浏览器原生默认外观。
- 不使用卡片套卡片；需要层级时使用边界、透明度、分割线和空间组织。

## 色彩系统

默认色彩应避免被单一紫色、深蓝或青色统治。建议语义方向：

- `space`：近黑背景，用于主画布。
- `panel`：半透明深色面板，用于对话和设置。
- `ink`：高亮正文。
- `muted`：次级说明和时间。
- `arc-cyan`：核心粒子和聆听状态。
- `arc-gold`：思考、启动和能量过渡。
- `arc-green`：成功、可用、记忆已保存。
- `arc-red`：错误、断连、危险操作。
- `line`：弱边界和 HUD 线条。

使用规则：

- 强发光色只用于核心状态、焦点和小面积反馈。
- 错误态必须明显，但不要用大面积红色覆盖整个界面。
- 状态色必须配合文字、图标或动画模式，不只依赖颜色。
- 避免装饰性渐变光球和无业务含义的大面积背景块。

## 字体与文字

- 默认字体使用系统无衬线字体，中文优先清晰可读。
- 聊天正文建议 `14px` 到 `16px`。
- HUD 标签和元信息建议 `11px` 到 `12px`。
- 页面标题和对话角色名保持克制，不使用夸张 hero 级字体。
- 字距保持默认，不使用负字距。
- 页面内不写功能说明书、快捷键教学或设计解释。

## 图标与组件

- 操作按钮优先使用 `lucide-react` 图标，并提供 `title` 或 tooltip。
- 图标按钮用于麦克风、静音、发送、停止、设置、历史等高频动作。
- 按钮圆角默认不超过 `8px`，除非是状态环、圆形麦克风按钮或视觉核心控件。
- 输入框必须支持发送、停止生成、禁用、错误和 loading 状态。
- 输入框默认隐藏在底边，通过小型底部识别区自动弹出，并保留点击把手兜底；语音入口保留在输入栏内作为次级能力，不常驻为 HUD。输入栏开合不得驱动粒子视角偏移或高频 React hover 状态，避免造成 WebGL 闪烁；输入弹框打开时必须以输入框本身作为事件源：组件从下往上闯入，上沿接触弦核空间并向上推出短促 3D 波前。产品效果采用实验台确认后的 `A+ 上沿起波`：允许在输入框外部、上沿锚点处叠加爆亮边线、火花和透视波面来增强因果关系，但不得做成输入框内部装饰动画、持续水波、偏心 3D 圆环或整体高速旋转。
- 记忆与隐私相关操作必须有明确文字，不只用图标。

## 动效规则

- 粒子动画服务状态反馈，不制造虚假计算。
- 常规 UI 动效建议 `120ms` 到 `220ms`。
- 粒子状态过渡可使用 `300ms` 到 `900ms`，但不影响输入响应。
- 聆听状态可响应音量；思考状态可呈现聚合或轨道加速；回答状态可呈现脉冲扩散。
- 流式 token 可触发短促且限速的粒子脉冲；错误可触发短促红色闪断；语音输入和播报可用低/中/高频与节奏分别影响粒子大小、轨道速度、核心亮度和波形。流式输出不得让弦核整体高速旋转或出现闪频。
- 弦核粒子层必须保持四面八方包裹核心的 3D 壳感，避免把虚线粒子排成单一圆饼盘；任何实体轨道都应低透明、非闭合或多轴分布，不能在特定视角压成一条像 `1` 的线。
- WebGL 场景必须在低性能设备上有降级策略。
- loading、流式回复和 TTS 播放不得造成布局跳动。

## 前端设计经验

- 对强视觉交互先做独立实验台确认方向，再移植到正式界面；实验台代码不进入产品事实，确认后的行为规则必须沉淀到文档。
- 视觉因果要清楚：如果用户认为“输入框弹出导致空间涟漪”，波源必须锚在输入框边缘，而不是弦核中心或屏幕中央。
- 避免把临时冲击波做成新的 3D 轨道环；偏心圆环会被误读为弦核结构错误。
- 粒子核心的美感来自包裹、呼吸和微扰，不来自大量粗亮闭合圆环；粗轨道线应谨慎使用。
- 实验台移植不能只保留行为和 class，必须保留让用户感知到因果的视觉证据；强视觉效果至少要验证外部波面层、关键动画名、尺寸、时长和发光强度，避免正式版退化成“有但不震撼”。

## 页面级验收

任何 UI 改动完成前，必须检查：

- 是否一眼能看出 AI 当前状态。
- 聊天内容和输入是否清晰可读。
- 粒子视觉是否没有遮挡文本和按钮。
- 常见窗口尺寸下是否没有文字重叠或按钮挤压。
- 麦克风、静音、停止生成、错误重试是否有清楚状态。
- 视觉层是否能在性能较弱时降级或关闭。
