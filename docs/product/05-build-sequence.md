# V2 分步实施顺序

状态：current
最后校验日期：2026-07-30

## 已确认顺序

应先搭建云端后端的最小基础，再开始手机 Web；但不能把“云端优先”理解为“后端全部完成后再做前端”。推荐按纵向切片逐步形成可运行闭环。

```text
决策与契约
  -> 三应用工程骨架
  -> 云端基础设施
  -> 身份纵向切片（云端 + 手机）
  -> 文字对话纵向切片（云端 + 手机）
  -> 任务纵向切片（云端 + 手机）
  -> 实时语音（云端适配 + 手机音频）
  -> 记忆与提醒
  -> 工作机客户端
```

## 为什么不是纯后端做到底

纯后端连续开发容易产生以下问题：

- API 字段和错误模型没有真实页面验证。
- 登录会话、跨域、HTTPS 和实时流问题发现过晚。
- 任务状态设计看似完整，但手机端无法自然呈现。
- 大量模块同时存在，却没有一条用户可用链路。

因此只允许云端“基础层”短暂领先；一旦身份公开接口可用，就引入最小手机 Web 进行真实联调。

## 第 0 步：定稿开发前决策

目标：消除会影响工程骨架的阻塞问题。

- 确认单仓库三应用。
- 确认手机 Web、云端和数据库技术栈。
- 确认耐久 Job、重试、Outbox 投递和提醒调度边界。
- 确认包管理、任务运行和测试工具。
- 确认邮箱登录、恢复和会话方式。
- 确认本地与 VPS 的可信 HTTPS 方案。
- 将公开 API 和事件草案转换成机器可校验 Schema。

验收：`docs/quality/02-phase-1-design-acceptance.md` 中 DR-001 至 DR-006 有明确结论。

## 第 1 步：三应用工程骨架

目标：建立物理边界，不实现完整业务。

- 创建 `apps/mobile-web`、`apps/cloud-server`、`apps/workstation-client`。
- 创建 `packages/contracts` 和契约生成/校验入口。
- 创建本地开发基础设施目录和统一任务入口。
- 为每个应用建立独立构建、测试和环境示例。
- CI 按应用路径运行，同时校验共享契约。

验收：三套应用可独立执行最小检查；没有应用导入另一个应用的内部源码。

## 第 2 步：云端基础设施

目标：让云端成为可部署、可迁移、可观察的空业务容器。

实施顺序：

1. 配置加载与环境校验。
2. 结构化日志、请求关联和错误处理。
3. 健康检查和就绪检查。
4. 主数据库连接和迁移框架。
5. Procrastinate 隔离技术验证、Worker 健康检查与重复投递故障注入。
6. 本地 Docker 依赖和 VPS 最小部署。
7. 身份模块的存储边界和公开 API 空契约。

暂不实现：实时语音、长期记忆、提醒、工作机连接和复杂任务编排。

验收：空服务可在本地和目标 VPS 启动，数据库迁移可前进和回滚，健康检查可诊断依赖状态。

## 第 3 步：身份纵向切片

目标：用真实手机页面验证第一条端到端链路。

云端：

- 邮箱注册、验证、登录、退出和当前用户接口。
- 会话撤销、速率限制和基础审计。

手机 Web：

- 最小页面壳、路由和 API 客户端。
- 注册、登录、退出和会话失效界面。
- 统一错误展示和加载状态。

验收：真实手机浏览器通过可信 HTTPS 完成注册登录，刷新后会话行为符合设计。

## 第 4 步：文字对话纵向切片

目标：验证会话、主 Agent 和流式响应，不引入音频复杂度。

云端：

- 创建会话和保存最终轮次。
- 接入一个主 Agent 模型适配器。
- 提供文字增量事件、取消和错误降级。

手机 Web：

- 会话列表和对话页。
- 文字发送、增量展示、取消和重试。
- 刷新后恢复最终轮次。

验收：完成一轮真实模型文字对话；模型失败不丢失已确认会话事实。

## 第 5 步：任务纵向切片

目标：验证“边聊边干活”最小业务核心，暂不连接工作机。

云端：

- 从对话形成任务草稿。
- 用户确认后生成正式任务。
- 实现最小任务状态机和事件查询。
- 使用一个无高风险副作用的云端测试执行器验证编排。

手机 Web：

- 任务确认卡片。
- 任务列表、详情、步骤和进度。
- 取消、失败和阻塞展示。

验收：任务未经确认不执行；确认后状态和结果来自任务事实，而非模型播报。

## 第 6 步：实时语音纵向切片

目标：把已验证的文字会话和任务能力换成低延迟语音入口。

- 选定首个实时语音供应商和适配器。
- 手机实现音频采集、播放、打断和会话状态。
- 云端提供短期实时连接引导、转写归一化和任务层衔接。
- 使用既有任务确认界面，避免语音层另建任务逻辑。

验收：真实手机完成可打断对话，并在语音中形成、确认和查询一个任务。

## 第 7 步：长期记忆、提醒与通知

- 增加记忆候选、确认、更正、删除和检索。
- 增加提醒计划、触发实例和消息中心。
- 后续再增加 Web Push（网页推送）。

## 第 8 步：工作机客户端

- 确定工作机技术栈、安装和升级方式。
- 实现设备绑定、出站连接、能力注册和任务租约。
- 先接入安全的演示执行器，再接 Codex CLI。
- 增加本地权限、审批、产物和断线恢复。

工作机端后置的原因：它依赖已经稳定的身份、任务状态、事件、审批和通知契约。如果先做工作机，会被迫在客户端重复实现尚未定稿的云端规则。

## 每一步的提交与验收规则

- 每个步骤建立独立方案台账和验收矩阵。
- 先提交契约与测试，再提交实现。
- 后端、前端和契约修改分批提交，但同一纵向切片必须共同验收。
- 每一步都产生可运行结果，不以“代码文件已创建”作为完成标准。
- 未完成步骤不得同时扩展下一个高复杂度领域。
