# V2 交付路线

状态：current
最后校验日期：2026-07-30

## 总体顺序

```text
文档与契约基线
  -> 技术决策与三应用工程骨架
  -> 云端最小基础
  -> 手机 Web + 云端文字纵向闭环
  -> 任务确认与进度闭环
  -> 实时语音闭环
  -> 记忆、任务与提醒
  -> 工作机连接与受控执行
  -> 稳定性、安全与多供应商增强
```

## 阶段 0：协作和产品基线

目标：建立可由 Codex 等开发工具一致读取的项目事实与门禁。

- 建立 Agent Context OS 极薄入口。
- 明确产品范围、三端职责、业务流程和架构边界。
- 建立可追溯项目记忆源。
- 建立 V2 分支和文档验证门禁。

退出条件：文档结构完整、无占位符、门禁通过、V2 可独立克隆理解。

## 阶段 1：云端与手机文字闭环

目标：先验证身份、会话、任务与事件链路，不被音频复杂度阻塞。

- 确定技术栈、三应用仓库组织和部署基线。
- 建立三套独立应用目录和共享契约源，但暂不同时实现三端业务。
- 先实现云端配置、健康检查、数据库迁移、日志和身份基础。
- 随后立即建立最小手机 Web 外壳，通过真实 API 完成登录纵向切片。
- 再按文字会话、任务草稿、任务确认和进度查询逐条闭环。
- 建立事件追踪、错误模型和最小运维能力。

退出条件：手机浏览器可安全访问云端并完成文字对话与任务查询。

详细顺序见 `product/05-build-sequence.md`。这里的“云端先行”只表示基础设施和事实模型先于界面，不表示完成全部云端能力后才开始手机端。

## 阶段 2：实时语音闭环

目标：接通自然、可打断、可降级的实时通话。

- 完成供应商评测并确定首个适配器。
- 实现浏览器音频采集、播放、打断和状态展示。
- 将语音转写接入主 Agent，而不是直接绕过任务层。
- 验证弱网、断线、限流和供应商故障处理。

退出条件：手机前台可完成稳定对话、打断和一次任务确认。

## 阶段 3：记忆、任务与提醒

目标：让助理具备跨会话连续性和可靠跟进能力。

- 实现短期上下文和长期记忆策略。
- 实现任务拆解、状态机、事件流和用户确认。
- 实现定时提醒与消息中心。
- 提供记忆与任务的查看、更正和删除入口。

退出条件：用户离开实时会话后仍可查询、继续和接收结果。

## 阶段 4：工作机端

目标：在不要求公网 IP 的前提下安全调用用户本地能力。

- 实现设备绑定、出站长连接和能力注册。
- 实现任务租约、进度回传、取消和断线恢复。
- 首先接入一个受控执行器，再逐步扩展 Codex CLI 等工具。
- 实现危险动作确认和本地产物边界。

退出条件：用户可从手机确认任务，工作机执行并可靠回传结果。

## 阶段 5：增强

- 增加实时语音和推理模型供应商。
- 优化自然音色、延迟、成本和路由策略。
- 增加 PWA、Web Push（网页推送）和多设备体验。
- 加强备份、审计、监控和灾难恢复。

## 路线规则

- 每个阶段开始前必须建立已确认的方案落实台账和验收矩阵。
- 后一阶段不得通过绕过前一阶段的公开契约来抢跑。
- 技术选型可以迭代，但产品职责和安全边界变化必须形成决策记录。
