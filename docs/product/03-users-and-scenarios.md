## 首要用户

V2 首先服务项目作者本人，设计上保留其他个人用户自部署或使用同类服务的可能，但首版不以组织级多租户为目标。

| 用户类型 | 是否需要工作机 | 主要诉求 |
|---|---:|---|
| 日常个人用户 | 否 | 实时聊天、长期记忆、记录事项、定时提醒和信息查询 |
| 开发人员 | 是 | 通过手机讨论方案、形成任务并驱动本地编程工具执行 |
| 办公人员 | 是 | 调查资料、处理文档、整理方案并跟踪产出 |

## 场景一：实时讨论并形成任务

1. 用户在手机网页发起实时语音会话。
2. 贾斯汀与用户讨论目标、约束和预期结果。
3. 主 Agent 将已确认信息整理成任务摘要或步骤清单。
4. 手机端展示或播报摘要，要求用户确认。
5. 用户确认后，任务进入调度；未确认时继续讨论或保存草稿。

成功标准：讨论内容不会直接被误当作授权执行，任务目标和验收条件可回看。

## 场景二：没有工作机的日常助理

1. 用户聊天、记录偏好或要求创建提醒。
2. 云端完成记忆更新、信息处理或提醒排期。
3. 到期后向手机 Web 端发送消息；用户再次打开页面时可查看完整记录。

成功标准：工作机离线或从未安装时，云端能力仍独立工作。

## 场景三：派发到个人工作机

1. 用户确认一个需要本地文件或编程环境的任务。
2. 云端查询已绑定且在线的工作机及其能力。
3. 主 Agent 生成受约束的任务包并选择执行器。
4. 工作机根据权限策略接受、等待确认或拒绝任务。
5. 执行期间持续回传阶段状态；完成后回传结果和产物引用。
6. 云端更新任务并通知手机端。

成功标准：用户不需要暴露工作机公网端口，也能从手机端持续获知真实状态。

## 场景四：执行中追问和调整

1. 用户询问某任务做到哪里。
2. 贾斯汀查询云端任务表和最近事件，不凭空生成进度。
3. 如用户要求修改范围，主 Agent 判断是补充信息、变更计划还是取消任务。
4. 已在执行的步骤只有在执行器支持并确认安全时才中断或调整。

成功标准：进度反馈来自任务事实；计划变更可追踪且不会造成重复执行。

## 场景五：危险动作确认

1. 执行器识别到删除、覆盖、发布、对外发送或其他高风险动作。
2. 任务进入 `waiting_approval` 状态并说明动作、目标和影响。
3. 用户通过受信任界面批准或拒绝。
4. 批准只对指定动作和有效期生效；拒绝后任务安全停止或改走替代方案。

成功标准：自然语言中的模糊同意不能被扩展为无限授权。
