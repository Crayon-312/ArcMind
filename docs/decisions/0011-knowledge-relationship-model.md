# 决策 0011：知识关系分层模型

状态：accepted
日期：2026-08-03

## 关系导航

- 所属领域：[决策内容地图](00-decisions-map.md)
- 上级入口：[项目文档总索引](../00-index.md)

- 验收标准：[V2 文档基线验收](../quality/01-documentation-acceptance.md)

## 背景

ArcMind V2 原有文档已经按产品、领域、架构、模块、业务、契约、决策、计划和质量分类，但目录分类不会自动形成 Obsidian（本地 Markdown 知识库工具）关系。修正前 57 个 Markdown（轻量标记文档）中有 49 个完全孤立，说明“文件已分类”不能等同于“知识已关联”。

## 决策

知识关系采用三个相互补充的层级：

1. 分类关系：项目总索引连接领域内容地图，领域内容地图连接本域文档，提供稳定入口和局部上下文。
2. 语义关系：正式文档直接连接真实的上游依据、下游细化、实现模块、业务流程、公开契约、约束决策和验收标准。
3. 历史关系：方案落实台账连接它发布的正式文档和决策，用于追溯变化，但不替代当前事实。

所有核心关系使用标准 Markdown 链接。Obsidian Canvas（可视化画布）、标签、搜索和关系图筛选只作为视图，不成为事实源。

## 关系约束

- 总索引不得直接承担全部文件清单，避免形成没有语义的单中心星状图。
- 每个正式领域必须有一个唯一命名的 `00-*-map.md` 内容地图，避免关系图出现多个同名索引节点。
- 当前有效或已接受的正式文档必须至少具有一条内部文档关系，不得成为孤岛。
- 不为了增加连线数量而链接无关文档；链接文字或所在小节必须能解释关系含义。
- 草稿文档可以进入领域地图以便评审，但其状态仍决定它不能作为实现依据。
- 新增、移动或废弃文档时，必须同步更新所属内容地图和受影响的语义关系。

## 结果

- 人类可以从总入口逐层进入领域，再沿业务含义追踪实现与验收。
- Agent（智能协作助手）可以用显式关系补足检索结果，而不依赖聊天上下文猜测上下游。
- 自动门禁可以阻止新的当前正式文档成为关系孤岛。
- 关系图用于发现结构缺口，不再只是文件数量的散点展示。
