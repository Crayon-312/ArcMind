# 决策 0001：V2 作为独立长期开发线

状态：accepted
日期：2026-07-30

## 背景

ArcMind 的产品方向已发生整体变化。继续在旧版代码和旧版协作文档上重构会把已废弃假设带入新系统，也难以判断哪些事实仍有效。

## 决策

- 保留 `main` 作为旧版项目分支，暂时冻结，不继续维护。
- 创建与 `main` 并列的 `v2` 长期开发分支。
- `v2` 使用孤儿分支，不继承 `main` 的文件树和提交祖先。
- 所有新版功能从 `v2` 派生功能分支并合并回 `v2`。
- 旧版事实只有在用户针对 V2 重新确认后才能进入 V2 文档或记忆源。

## 结果

- 优点：边界干净，可以从产品事实重新设计架构。
- 代价：不能依赖普通合并自动复用旧代码；未来复用必须逐项评审。
- 风险：GitHub 默认分支仍可能指向旧 `main`，仓库首页需要清晰说明 V2 状态。

## 验证

- `v2` 首个提交没有 `main` 祖先。
- 本地和远端均存在独立 `v2`。
- `main` 现有工作区内容未被改写。
