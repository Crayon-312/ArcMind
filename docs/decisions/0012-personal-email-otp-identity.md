# 决策 0012：本人优先的邮箱验证码身份基线

## 背景

首版只保障作者本人使用，但仍需保留普通个人用户、登录身份和浏览器会话的清晰边界。若因为“只有一个人”而省略会话撤销、验证码一次性消费或限速，浏览器凭据泄漏、邮件轰炸和重放仍会破坏产品事实与手机端可用性。

## 决策

- 首版只允许部署配置中的一个归一化邮箱登录，不提供公开注册入口、密码、组织、角色、多租户或管理员后台。
- 邮箱验证码同时承担首次激活、后续登录和邮箱可控性恢复，不再建立一套独立密码找回流程。
- 验证码为 6 位数字，10 分钟过期，最多失败 5 次；成功后立即消费，新挑战签发时旧挑战失效。数据库只保存验证码摘要、过期时间、尝试次数和消费状态。
- 发信初始限速为同一邮箱 15 分钟最多 3 次、同一来源 IP（互联网协议地址）15 分钟最多 10 次；验证同时受挑战次数和来源 IP 限制。生产配置可以收紧，但不得关闭。
- 登录成功后生成至少 256 位随机会话令牌，数据库只保存令牌摘要。浏览器使用 `__Host-arcmind_session` Cookie（浏览器会话凭据），并设置 `Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/`，不设置 `Domain`。
- 允许本人在多个浏览器保持独立会话；会话空闲 7 天失效、绝对 30 天失效。支持退出当前会话和撤销全部会话，撤销同时终止相关 SSE（服务器发送事件）连接。
- 手机 Web 与 API（应用程序接口）同源部署。改变状态的请求校验 `Origin`（请求来源）和幂等标识，不开放任意跨域携带会话凭据。
- 开发和测试使用邮件捕获器或测试适配器；生产通过标准 SMTP（简单邮件传输协议）适配器连接外部中继，真实凭据只进入部署环境。

## 状态与错误

验证码挑战只使用 `pending -> consumed`、`pending -> expired` 和 `pending -> locked` 三条终态路径；任何终态都不能重新激活。会话只使用 `active -> expired` 或 `active -> revoked`，服务端校验时间和撤销状态，不能只依赖浏览器删除 Cookie。

公开错误保持统一语义：发起验证码始终返回已接受；验证码无效、过期或已消费统一返回挑战不可用；超过发送或验证限制返回 `RATE_LIMITED` 和安全的等待时间；会话失效返回 `AUTH_SESSION_EXPIRED`。日志遮盖邮箱并禁止记录验证码和原始会话令牌。

## 恢复边界

只要用户仍控制邮箱，就能通过新验证码恢复访问，并在登录后撤销其他会话。邮箱账号本身丢失控制不由 ArcMind 绕过，首版不提供安全问题、备用密码或人工数据库改写后门；应先通过邮件服务恢复邮箱控制。

## 候选比较

| 候选 | 结论 |
|---|---|
| 邮箱一次性验证码 | 采用；没有密码存储和找回链路，适合本人优先，同时保留普通账户与会话模型 |
| 邮箱魔法链接 | 暂不采用；跨应用跳转、链接扫描器提前消费和手机默认浏览器切换使首版状态更复杂 |
| 密码 + 邮箱验证 | 不采用；增加密码强度、泄漏、重置和撞库治理，当前没有业务收益 |
| 第三方社交登录 | 不采用；增加外部身份供应商、回调域名和账号合并问题 |
| 无登录或固定共享密钥 | 禁止；无法安全撤销浏览器会话，也无法扩展到工作机绑定 |

## 验收门禁

- 覆盖允许邮箱、非允许邮箱、重复发送、过期、错误 5 次、旧码失效、一次性消费和并发消费。
- 覆盖当前退出、全部撤销、空闲过期、绝对过期、撤销后 SSE 断开和原始令牌不落库。
- 覆盖同源 Cookie、来源校验、统一错误、邮箱遮盖、发信故障和限速。
- 真实手机通过可信 HTTPS（安全超文本传输协议）完成验证码登录和刷新恢复后，身份纵向切片才能验收。
