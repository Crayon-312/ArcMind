# 验收口径：第一阶段设计就绪

状态：draft
最后校验日期：2026-07-30

第一阶段目标是实现云端与手机 Web 的安全文字闭环。在创建业务代码骨架前必须通过以下门禁。

## 必需决策

| 编号 | 决策 | 通过条件 |
|---|---|---|
| DR-001 | 手机 Web 技术栈 | passed：决策 0006 已覆盖框架、构建、状态与测试基线；音频真机验证仍归实时语音阶段 |
| DR-002 | 云端技术栈 | passed：决策 0005 和 0007 已覆盖 API、实时连接能力、Agent 编排、测试与部署边界 |
| DR-003 | 数据与迁移 | passed：决策 0008 与架构 11 已明确主数据库、迁移、备份、检索和开发环境 |
| DR-004 | 身份机制 | 明确邮箱验证、登录、恢复、撤销和速率限制 |
| DR-005 | HTTPS 部署 | 目标手机浏览器认可，具有自动续期和恢复方式 |
| DR-006 | 实时事件通道 | 明确文字流、任务进度和重连策略 |
| DR-007 | 模型接入基线 | open：LangGraph 框架已定，具体模型供应商与降级策略尚未选择 |

`passed` 只代表对应设计决策已经完成，不代表第一阶段总门禁通过。DR-003 至 DR-007 的开放项仍会阻止创建完整业务骨架。

## 必需设计产物

- 核心领域模型得到用户确认或以明确变更记录定稿。
- 身份、会话和任务模块的字段、状态、异常和验收文档完整。
- 云端公开 API 形成可机器校验的 Schema。
- 数据表与领域对象映射、索引和所有权明确。
- 手机端页面地图、交互状态和错误展示完成。
- Docker（容器平台）开发与 VPS 部署拓扑形成可复现说明。
- 单元、集成、契约和端到端测试矩阵形成。

## 首个文字闭环验收

| 场景 | 预期 |
|---|---|
| 邮箱注册和登录 | 用户可进入手机 Web，异常状态清晰 |
| 创建文字会话 | 云端保存会话并返回稳定会话标识 |
| 发送文字消息 | 主 Agent 返回流式或渐进结果，刷新后最终轮次可恢复 |
| 形成任务草稿 | 目标和计划版本可见，未经确认不执行 |
| 确认任务 | 生成正式任务并进入真实状态机 |
| 查询任务 | 页面刷新和重新登录后状态一致 |
| 会话失效 | 实时和普通请求均停止继续访问，并引导重新登录 |
| 模型故障 | 会话和任务事实不丢失，允许重试或稍后继续 |

## 不通过处理

任何必需决策保持 `open`、接口仍含未说明字段、或端到端验收无法关联任务事实时，不进入完整业务实现。允许建立一次性技术验证，但验证代码必须与正式架构分离并有清理结论。
